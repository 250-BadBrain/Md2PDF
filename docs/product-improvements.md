# 五项改进交付记录

日期：2026-10-02。按讨论顺序实施了以下五项改进。

## 1. 纯前端 PDF 导出（按最新要求调整）

项目完全通过静态资源运行，无 PDF API 或 Node 生产服务。默认可搜索 PDF 调用独立 iframe 的浏览器打印，正文、链接和矢量图形由浏览器打印引擎输出；用户在对话框中选择另存为 PDF，并关闭浏览器自带页眉页脚。实现使用 [浏览器打印](https://developer.mozilla.org/en-US/docs/Web/API/Window/print)。

图像 PDF 使用 html2canvas + jsPDF 直接下载。批量 ZIP 固定使用图像 PDF，正文不能搜索；可搜索 PDF 需逐文档打印保存。上传文档在浏览器内处理，不提交到导出服务。远程图片仍会请求其原地址。

此前新增的原生服务、服务脚本、Vite 中间件和运行时 Playwright 依赖已移除。Playwright 仅保留为开发测试工具，测试通过捕获前端打印 HTML 后生成 PDF，验证文本与纸张尺寸。
## 2. 复杂分页

嵌套有序列表的续页编号得到保留。超长普通表格行按单元格内容拆为多个页面，保持正文大小，并在每页重复表头。嵌套提示块内的分页标记生效。保留原有标题衔接、代码高亮、脚注锚点和图形缩放。

含 rowspan 的表格仍作为完整结构处理；过高的合并表格或不可拆图形可能缩小。这一边界避免跨页改变合并单元格关系。

## 3. 长文档性能

预览更新时保留旧页面并显示加载状态，更新完成前禁止下载过期结果。分页支持取消，周期性让出主线程，已测量页面及时从 DOM 移除。最多缓存四份结果，总预算 8MiB，替换上传资源时清除缓存。

页面占位尺寸保持完整，只有视口附近的内容挂载到 DOM；提供页码跳转，目录与脚注跨页跳转会先加载对应页面。45 页文档测试验证实际挂载页数少于 10，跳转到最后一页仍能显示正确正文。超大单次 Markdown 解析仍在主线程，未引入 Worker。

## 4. 可保存排版设置

界面支持 A4/A5/Letter、横纵方向、边距、字体、正文大小、行距、页眉页脚、页码及章节分页。设置自动保存并提供恢复默认值；存储不可用时本次设置仍有效。YAML 中明确指定的值优先。

测量、预览、打印 PDF 和图像 PDF 共用页面几何与字体配置。已验证 A5 横向实际 PDF 的页面尺寸、中文文本，以及重载后的恢复和 YAML 覆盖行为。Chromium 的物理尺寸存在不足 1pt 的像素取整误差。

## 5. 回归验证

- 17 项单元测试：Markdown 语法、安全清洗、配置验证及优先级。
- 17 项浏览器测试：内容完整性、复杂分页、多行页眉空间、打印 PDF 文本提取、图像兼容、ZIP、虚拟预览、排版设置、纯前端零 API 请求和截图对比。
- 两页 Markdown 方言截图基线，覆盖常用文本、表格、代码、数学、图表、提示容器、HTML 和脚注，已人工检查。
- 生产构建通过；依赖审计 0 漏洞。应用导出不依赖后端。
- 实际两页 A4 PDF 和 A5 横向 PDF 经 Poppler 渲染并检查，中文、表格、公式、Mermaid、页眉页脚正常。

截图基线采用当前 Windows 字体环境。更换系统、字体或浏览器大版本时，需要人工检查后更新该平台基线。构建仍有大型第三方 Mermaid / Markdown 包的大小提示，不影响导出。
