# 质量保障与文档工作流

本轮按六项顺序实施，生产环境继续只需静态托管 `dist`。

## 自动化验证

新增 GitHub Actions：Linux 上使用 Node 24，依次运行 `npm ci`、单元测试、构建、Chromium 全部非截图基线检查、Firefox/WebKit 跨浏览器检查；Windows Edge 检查已有两页视觉基线。trace、失败截图和报告保留七天。fixture 指定 LF checkout，保证官方例集哈希在 Windows 与 Linux 一致。

工作流依照 [Playwright CI 文档](https://playwright.dev/docs/ci) 使用 `playwright install --with-deps`。远程工作流需要推送后运行，本次本地配置和测试不能替代远程结果。Firefox 在本机仍返回 `spawn UNKNOWN`，没有宣称验证通过。

## 性能与导出

分页以约 8ms 的工作预算让出主线程，去除逐行 `indexOf` 的二次扫描；文本拆分改为逐节点索引，避免为每个字符创建对象，并保留 Unicode 代理对。性能基准包含 350 段正文、300 行表格和 12 张 SVG 图片，生成 35 页；本机多次测量约 40–70ms，验证尾部正文、尾行、图片数及测量 DOM 清理。该数字不含解析、Mermaid 和图像 PDF 导出，也不是任意文档的速度保证。

图像 PDF 三档参数：小体积 1×/JPEG 0.72，均衡 1.5×/0.85，高清 2×/0.98（保留原默认）。选择保存在浏览器中，已验证小体积结果小于高清结果。ZIP 每卷最多 10 个文件或约 32MiB 已生成 PDF；清空上一卷状态后继续，单个大 PDF 可以超过阈值。生成当前 PDF 仍需保留其完整 jsPDF 内容，内存并非固定上限。分卷与多文件下载提示在批量界面可见。

## 本地项目

IndexedDB 原子保存正文、路径、排版和图片二进制数据，读取时还原 Blob；项目不发送到服务端。每个项目保留五个不同版本，图片内容用 SHA-256 区分，防止同尺寸图片替换被当作未修改。当前项目自动保存，旧文本草稿继续作为回退；恢复前发生编辑时不会覆盖新输入。项目库可另存新项目、打开、删除和恢复历史。

项目包是 `project.json` 与 `assets/*.bin` 的 ZIP。导入先检查中央目录声明的展开大小、条目数量、路径和格式，再核查清单、资源实际大小与 MIME；拒绝父目录、绝对路径、加密、多卷、ZIP64 与不支持格式。限制为 100MiB、200 张图片、2Mi 正文字符，浏览器实际配额可能更低。浏览器清除站点数据会删除项目和历史，导出包用于备份。

## 源码定位

Markdown 块 token 输出原始文档起止行号，计入 YAML 偏移，Worker 同样保留映射。清洗、图片 figure 转换、分页片段和虚拟预览保留这些标记。映射只影响导航，不放宽 HTML 安全过滤；官方例集比较仅忽略新增导航属性，差异基线文件没有更新。

编辑区根据实际字体和宽度测量自动折行，预览定位索引在分页变化时建立，同步滚动不会重复解析整份 HTML。未开启同步时不在每次键入后重建折行镜像。点击正文和行号诊断可以选中源码块。跨页长块映射的是整个原始块，不是 PDF 内某个字符；原始 HTML 不附加标记，包含 title/textarea/xmp/script/style/plaintext 标签时关闭映射，防止属性被误当成正文。

## 专业排版

- `minParagraphLines: 1..4` 控制段落分页两侧的最少行数，默认 1；依赖 DOM Range 的实际行矩形，不按字符猜测行数。不可拆情况允许回退并显示缩放提示。
- `footnotes: page-bottom` 在正文每次测量时按该页引用计算脚注空间，脚注固定于内容区域底部。单页脚注预算为正文区域的约 40%；长注和拥挤脚注续页，文本与回链保留。极大不可拆脚注内容缩小并提示。
- `figureNumbers: true` 为图片/图表添加编号和目标 ID，`[@ref](#目标)` 显示编号；缺失目标进入诊断。自动 ID 避让已有 ID，显式图片 ID 转移到 figure。
- `wideTables: true` 将超过内容宽度或至少八列表头的表格放入独立横向页，再恢复文档方向。每页保存实际尺寸，预览窗口化、打印命名 @page、jsPDF 页面和内部链接测量均使用对应尺寸。无法拆开的超大合并行组仍可能缩小。

## 方言模式

`dialect` 支持 `document`、`commonmark`、`gfm`、`obsidian`，默认 document。解析器按模式与软换行设置独立缓存。

CommonMark/GFM 使用标准软换行，关闭数学、Mermaid、目录、脚注和其他文档插件；GFM 保留表格、删除线、任务列表和扩展自动链接。生产输出仍有图片处理和 HTML 安全过滤，因此不是未经修改的标准 HTML。YAML 是应用的配置头部，所有模式都识别。

Obsidian 模式在文档扩展基础上支持文档内标题/块双链、别名和图片嵌入。跨文档关系、完整 vault、查询插件、笔记嵌入与执行式语法不支持。代码中的双链不转换，标签文本经过转义。

运行 `npm test`、`npm run build`、`npm run test:browser`。离线测试始终需要先构建。新增专项涵盖真实质量差异、11 文件 ZIP 分卷、混合方向 PDF 物理尺寸、长注完整性、正文/脚注不重叠、脚注图片的尺寸等待和缩放、历史与图片恢复、同尺寸图片替换、跨项目草稿隔离、危险 ZIP 路径、源码偏移与虚拟页面定位、模式隔离和双链转义。
